# 界面方向与设计规则

状态：提案。还没有可运行的界面，下面的判断来自需求和竞品资料，不是对实际画面的诊断。M1 做出第一个代表区域（改动列表 + diff + 提交区）后，按 [界面审查](#验证方式) 复核并更新本文件。

本文件是共享视觉规则的唯一维护位置；实现时具体取值写进前端主题文件（`src/styles/theme.css`，待建立），本文件只记录选择和理由。

## 1. 产品任务决定布局

这是一个**持续操作的工作台**：用户在「看改动 → 挑选 → 写信息 → 提交 → 推送」之间反复循环，一次会话里要做很多次。所以：

- 改动列表、diff、提交区三者的关系必须一眼看清，常用控件位置固定不动。
- 信息密度要高（像 IDE），但可点击的目标不能太小。
- 键盘优先：焦点在哪个区域、选中了什么，要始终清楚可见。
- 状态（已暂存、冲突、进行中的合并、正在推送）必须有文字或图形，不只靠颜色。

## 2. 两个布局候选

| | A：工作区优先（IDEA / Fork 的改动视图） | B：时间线优先（GitKraken 的图为主） |
| --- | --- | --- |
| 主画面 | 左：改动列表；中右：diff；左下：提交区。日志是同一窗口的另一个视图 | 上：提交树图占大半；顶行是「未提交改动」，点开后在右侧面板暂存和提交 |
| 好处 | 核心循环（挑选和提交）占最大空间；按行暂存需要宽的 diff 区 | 历史和分支关系一直可见 |
| 代价 | 看历史要切视图 | diff 被挤到侧栏，按行挑选很局促；日常提交时树图大多用不上 |

**选 A。** 理由：MVP 的核心任务是挑着提交，按行暂存需要宽 diff；看历史的频率低于提交。从 B 借一点：日志视图第一行固定为「未提交的改动（N）」，点它回到改动视图。

## 3. 区域与层级

```
┌ 工具栏：仓库名 ▾ │ 分支 ▾ ↑2 ↓1 │ 获取  拉取  推送 │ 视图切换：改动 | 日志 │ ⚙ ┐
├ 项目树（可收起/调宽）┬ 改动栏（可调宽，默认 320px）─┬ 主区（标签：改动 | 历史；路径）───────┤
│ 项目文件树           │ 改动列表（分组、可折叠）     │ diff（工具条：统一/对比、忽略空白）    │
│ （过滤/搜索/状态徽标）│                             │ 或 文件历史与提交 diff                  │
│                      ├ 提交区（信息框、AI、提交）───┤                                        │
├ 底部：操作日志（默认折叠为一行状态栏）──────────────┴────────────────────────────────────────┤
```

- 第一层级：diff 内容、改动列表与项目文件树（任务对象）。
- 第二层级：提交区（每次循环的终点），提交按钮是全界面唯一的实心强调色按钮。
- 第三层级：工具栏和状态栏。推送、拉取用图标 + 文字的次级按钮，有待推送提交时推送按钮显示数量徽标。
- 冲突、合并进行中这类全局状态用工具栏下方的横幅，不用弹窗打断。
- 会丢数据或改写已推送历史的操作（丢弃改动、修改已推送的提交）必须用确认对话框，默认焦点在「取消」，确认按钮用 `danger` 样式，回车不直接确认（PRD R-17、R-06）。

## 4. 字体

| 角色 | 字体 | 大小 / 行高 |
| --- | --- | --- |
| 界面 | 系统字体：`-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif` | 13px / 20px |
| 代码、diff、哈希 | `"JetBrains Mono", "Cascadia Code", ui-monospace, Menlo, Consolas, "Noto Sans Mono CJK SC", monospace` | 12.5px / 20px |
| 区域标题 | 界面字体，600 字重 | 12px，字距略宽，不用全大写（中文无意义） |

不打包网络字体；JetBrains Mono 若要内置，按 OFL 许可放在应用资源里（M1 决定）。

## 5. 颜色角色

中性色用 Radix Slate，强调色用 Radix Blue（工具类界面清晰、偏冷）。浅色和深色模式分别映射，不是简单取反；默认跟随系统。

| 角色 | 用途 | Radix 色阶（浅 / 深各自取对应阶） |
| --- | --- | --- |
| `bg` / `surface` / `surface-raised` | 窗口底、面板、弹层 | Slate 1 / 2 / 3 |
| `border` / `border-strong` | 分隔线、输入框 | Slate 6 / 7 |
| `text` / `text-muted` | 正文、次要信息 | Slate 12 / 11 |
| `accent` / `accent-text` | 主按钮、焦点环、选中行左侧标记 | Blue 9 / Blue 11 |
| `selection` | 列表选中行、diff 选中行背景 | Blue 4（获得焦点时）/ Slate 4（失焦时） |
| `status-added` | 新增、未跟踪文件 | Grass 11（文字 / 图标） |
| `status-modified` | 修改 | Amber 11 |
| `status-deleted` | 删除（另加删除线） | Red 11 |
| `status-renamed` | 重命名 | Teal 11 |
| `status-conflict` | 冲突（另加 ⚠ 图标） | Tomato 11，横幅背景 Tomato 3 |
| `diff-add-bg` / `diff-add-strong` | 新增行背景 / 行内变化字符 | Grass 3 / Grass 5 |
| `diff-del-bg` / `diff-del-strong` | 删除行背景 / 行内变化字符 | Red 3 / Red 5 |
| `danger` / `danger-border` | 会丢数据或改写历史的确认按钮（S10 丢弃、S11 修改已推送提交）：红色文字 + 红色描边，不做实心 | Red 11 / Red 8 |

文件状态颜色沿用 VS Code 的习惯（M 黄、A/U 绿、D 红），因为用户也常用编辑器侧栏；每个状态都同时显示字母（M、A、D、R、U、!），不只靠颜色。diff 行首始终显示 `+` / `-`，色盲用户也能分辨。

对比度：M1 用实际组合测量（文字对各自背景），记录测量方法和结果；不引用 Radix 对单个组合的说明来声称整页达标。

## 6. 尺寸与密度

- 列表行高 24px，diff 行高 20px，工具栏 40px，状态栏 24px。
- 点击目标最小 24×24px（图标按钮带 4px 内边距）。
- 圆角：弹层和对话框 8px，按钮和输入框 4px，列表行不加圆角。
- 阴影只用于浮在内容上的弹层（分支弹窗、命令面板、菜单）。
- 面板之间用 1px 分隔线，不用卡片阴影分区。

## 7. 动效

- 只用于说明状态变化：暂存后的行从未暂存区淡出（120ms）、面板展开收起（150ms）、进行中的操作显示状态栏转圈。
- 尊重系统「减少动态效果」设置：关闭所有过渡，只保留进度指示。
- 不加装饰性动画。用 CSS 过渡实现，不引入动画库（planner 用的 framer-motion 在这里不需要）。

## 8. 组件选型（候选，M0 / M1 核实版本和许可证）

| 需要 | 候选 | 理由 | 备注 |
| --- | --- | --- | --- |
| 基础组件（按钮、对话框、菜单、弹层、Tabs、Tooltip） | shadcn/ui（基于 Radix Primitives，源码拷进项目）+ Tailwind CSS 4 | React 项目、需要深度定制密度；planner 已用 Tailwind 4 和 lucide 图标，经验可复用 | 默认皮肤按本文件重新定主题 |
| 命令面板、分支弹窗过滤 | cmdk（shadcn 的 Command 组件） | 键盘过滤列表现成 | |
| 可调宽分栏 | react-resizable-panels | 记住面板宽度（R-14） | |
| 长列表虚拟滚动（改动列表、日志、diff） | @tanstack/react-virtual | 5 万条提交、超长 diff | |
| diff 渲染 | **自写**虚拟化 diff 组件 + 语法高亮（Shiki 按需加载语言，或 Lezer，M1 spike 二选一） | 按行选择、行号区点击、空格暂存这些交互要完全可控；Monaco 体积大，行选择定制成本高 | v2 的三栏合并再评估 CodeMirror 6 的 merge 扩展 |
| 提交树图 | 自写：Rust 侧算每行的「轨道」布局，前端用 SVG 或 Canvas 画线 | 布局算法要和分批加载配合 | M4 |
| 图标 | lucide-react | 和 planner 一致 | |

本节没有打开过上述组件的在线示例，只是基于官方文档描述的能力做的候选判断；M1 实际接入时记录看过的示例和取舍。

## 9. 窗口与平台

- MVP 用系统原生窗口边框（不学 planner 的 `decorations: false` 自绘标题栏），减少拖动、Windows 贴靠布局、macOS 全屏这些平台问题。macOS 后续可考虑 `titleBarStyle: Overlay`。
- 菜单：macOS 提供标准应用菜单（编辑菜单要有，否则复制粘贴快捷键失效）；Windows / Linux 不显示菜单栏，功能都在工具栏和命令面板里。
- 高 DPI、缩放 125% / 150% 下检查 1px 分隔线和树图线条是否清晰。

## 10. 文案

- 操作名和结果一致：「暂存所选」「提交」「推送 2 个提交到 origin/main」，不用「确定」。
- 错误信息说清下一步：「远程有新提交，请先拉取」配「拉取」按钮。
- git 术语首次出现保留英文对照（获取 fetch、变基 rebase），之后只用中文。

## 验证方式

- 截图只能证明外观；功能是否成功以验收测试的命令行核对为准。
