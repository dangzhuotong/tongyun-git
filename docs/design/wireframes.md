```

- 左栏宽度可拖动；「提交」是界面上唯一的实心强调色按钮。
- 文件状态字母和颜色：M 黄、D 红加删除线、R 青、U 绿；冲突文件为 `!` + ⚠。
- 空状态（没有改动）：主区显示「工作区干净」和最近一次提交的标题。
- 勾选「修改上一次提交」后：信息框填入 HEAD 的信息，按钮文字变为「修改提交」，勾选框旁显示 HEAD 短哈希；没有提交或合并进行中时勾选框置灰，悬停说明原因（R-06）。
- 未配置 AI 时「✦ AI 生成」显示为「✦ 配置 AI」，点击打开 S8。
- 改动列表右键菜单：暂存 / 取消暂存 · 丢弃改动…（Ctrl+Alt+Z）· 复制路径 · 在文件管理器中显示。丢弃后状态栏上方出现提示条：「已丢弃 2 个文件的改动 [撤销]」，10 秒后消失（R-17）。

## S3 diff 行选择（R-05、R-16）

```
│ [暂存所选 ␣]  已选 2 行                                                     │
│  40 40   function save(u) {                                                 │
│▌ 41    -   return db.put(u)          ← 选中（蓝色背景 + 左侧强调条）         │
│     41 +   validate(u)                                                      │
│▌    42 +   return db.put(u)          ← 选中                                  │
│  42 43   }                                                                  │
```

- 点行号区选中一行，Shift+点扩选；键盘 ↑↓ 移动、Shift+↑↓ 扩选、`a` 选整个 hunk、空格执行。
- 暂存后：被暂存的行从这里消失（淡出 120ms），提示条显示「已暂存 2 行」。要撤回就切到已暂存 diff 选中这些行取消暂存（R-05）。
- 二进制或换行符整体变化的文件：工具条显示「此文件只能整体暂存」，行选择不可用。

## S5 分支弹窗（R-08、R-09）

```
        ┌────────────────────────────────────────┐
        │ 过滤分支…                    [+ 新建分支]│
        │ 本地                                     │
        │ ✓ main              ↑2 ↓0               │
        │   feature/anim      ↑0 ↓3   origin/…    │
        │ 远程                                     │
        │   origin/main                            │
        │   origin/feature/login   （本地无）      │
        └────────────────────────────────────────┘
```

新建分支：

```
        ┌────────────────────────────────────────┐
        │ 新建分支   起点：HEAD (4b8fd47)          │
        │ 名称 [feature/login              ]       │
        │ ☑ 创建后切换                             │
        │                     [取消]  [创建]       │
        └────────────────────────────────────────┘
```

名称不合法时输入框下方显示原因（例如「不能包含 ..」），创建按钮不可用。

切换被阻止：

```
        │ 无法切换到 feature/anim：下列文件的改动会被覆盖 │
        │   src/api/user.ts                             │
        │ 请先提交这些改动。                   [知道了]  │

## S8 设置·AI（R-07、R-13）

```
┌ 设置 ─────────────────────────────────────────────────────────┐
│ 通用   Git   [AI]   外观   快捷键                              │
│                                                               │
│ ☑ 启用 AI 功能                                                │
│ 提供方     ( ) KIE   (•) OpenAI 兼容接口   ( ) Ollama          │
│ 地址       [https://api.deepseek.com/v1               ]       │
│            请求地址：https://api.deepseek.com/v1/chat/completions│
│ 模型       [deepseek-chat（示例）                     ]       │
│ Key        已加密保存在本机   [修改]  [清除]                   │
│ 超时       [30] 秒                                            │
│ 提交信息语言 [跟随仓库最近提交 ▾]   ☐ Conventional Commits    │
│ 发送上限   [20000] 字符                                       │
│ 不发送内容的文件  .env*  *.pem  *.key  id_rsa*  *secret*  [+]  │
│                                   [测试连接]  ✓ 连接成功       │
└───────────────────────────────────────────────────────────────┘
```

按提供方变化的部分：

- KIE：地址固定显示 `https://api.kie.ai`（只读），请求地址行显示 `https://api.kie.ai/<模型>/v1/chat/completions`。
- Ollama：地址默认 `http://localhost:11434`；模型是下拉框（从 `/api/tags` 读取，旁边有刷新按钮，读不到时允许手填）；Key 一行标「可选」。地址不是本机且是 http 时，地址下方显示黄色提示「内容会明文经过网络」。
- 未保存 key 时 Key 一行是密码输入框 + [保存]；保存后只显示「已加密保存在本机」，不回显任何字符。
- 加密存储不可用时 Key 一行置灰：「本机加密存储不可用，无法保存 key。」可改用 Ollama。
- 第一次打开、还没选提供方时三个选项都不选，下面的字段隐藏，只显示一句「选择一个 AI 提供方。应用不内置 key，需要你自己填写。」

「测试连接」发一个极短请求，只显示成功或错误原因（401、超时、地址不通、模型不存在），不显示 key。

## S10 丢弃改动确认（R-17）

```
        ┌──────────────────────────────────────────────────┐
        │ 丢弃 3 个文件的改动？                             │
        │ 恢复到上次提交（已暂存的部分也会被丢弃）：         │
        │   M  src/api/user.ts   （有已暂存的部分）          │
        │   M  src/db.ts                                   │
        │ 将删除：                                          │
        │   U  src/api/cache.ts                            │
        │ 丢弃前会自动保存快照，可以撤销。                  │
        │                                                  │
        │              [取消]  [丢弃 3 个文件的改动]         │
        └──────────────────────────────────────────────────┘
```

- 「取消」是默认焦点；回车和空格不会触发丢弃，Esc 关闭。确认按钮用危险样式（红色描边和文字，不是实心），与提交按钮区分（[界面方向](ui-direction.md) 第 5 节 `danger`）。
- 有超过快照上限的文件时，在列表里该文件后标「⚠ 丢弃后无法恢复」，底部那句改为「除标 ⚠ 的文件外，丢弃前会自动保存快照」。
- 撤销时遇到已被改过的文件：

```
        │ 下列文件在丢弃后又被修改，撤销会覆盖当前内容：     │
        │   src/db.ts                                      │
        │                  [跳过这些文件]  [覆盖]            │
```

```
        ┌──────────────────────────────────────────────────┐
        │ 上一次提交已推送到 origin/main                    │
        │ 4b8fd47 feat: 素材来源规则                        │
        │ 修改后本地和远程会分叉，之后推送会被拒绝。         │
        │ 本应用不提供强制推送，需要在命令行处理。           │
        │ 如果只是补改动，建议改为新建一个提交。             │
        │                                                  │
        │                    [取消]  [仍然修改]             │
        └──────────────────────────────────────────────────┘
```

默认焦点在「取消」，回车不直接确认；「仍然修改」用危险样式。
