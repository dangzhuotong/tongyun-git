# 决策 0003：工作区快照使用带清单的 Git 对象

状态：已实施；本机源码验证见 [工作流验证记录](../testing/runs/2026-10-11-workflows.md)，跨平台安装包待验收。
日期：2026-10-11

## 问题

agent 会话、未暂存改动搁置、按行丢弃需要准确保存普通文件，包括删除、未跟踪文件、CRLF 和部分暂存。旧丢弃快照把 `/` 编码成 `__`，会产生路径碰撞，且恢复暂存区时误用了工作区内容。

## 决定

- 用 JSON 清单记录仓库绝对根目录、HEAD、时间、用途和原始相对路径，路径映射到可空的 blob OID 和文件模式；不进行有损路径编码。
- 快照 commit 的树包含清单和所有被引用 blob，保证 git gc 不回收恢复内容。引用置于 `refs/tongyun/snapshots/*`；整文件丢弃保留 `refs/tongyun/discard/*` 别名及最近 20 次保留策略。会话/搁置/撤回备份由用户显式删除，不静默丢掉恢复点。
- 工作区与 index 分别记录。会话恢复、搁置、按行丢弃只写工作区；整文件丢弃及其撤销分别恢复工作区和 index。
- agent 来源以用户显式开始和结束会话界定，不猜测进程或读取 agent 私有日志。会话内手动改动也纳入，因此界面明确说明；结束后以结束状态作为覆盖保护基线。
- 恢复要求 HEAD 不变，检查用户预览时的文件/index 版本，并在每个文件写入前复核；结束后新手动改动跳过。恢复前保存可再撤回的备份。
- 普通文件单个 50 MB、工作区合计 200 MB；超限的会话创建整体失败。忽略的未跟踪文件不捕获；子模块和符号链接不遍历；所有写入验证相对路径和父目录，不能跨越符号链接或触及 `.git`。
- 文件以同目录临时文件写入再替换，保留可执行位。无法恢复不冒充成功。
- 新工作流 IPC 在后台执行并串行；Git CLI 均复用 CliRunner。无新增依赖。

## 考虑过的方案

- stash：适合 Git 原生贮藏，但不适合不动 index 的 agent 全工作区基线，也不能直接记录不存在的文件和独立覆盖基线。
- 工作区复制到普通目录：占用额外文件布局、易漏权限且不能依靠 Git 对象的可达性检查。
- 有损路径拼接：拒绝，无法区分嵌套路径与含分隔编码的真实文件名。

## 后果与验证

会话和搁置对象只存在本地，普通 push 不发送这些引用；用户主动 mirror push 会包含自定义引用，快照不是加密保险箱。全工作区快照的容量与速度受仓库规模影响，开始失败时应缩小工作区，而不是悄悄漏文件。旧丢弃格式保留原始引用但不自动按有损路径恢复。

验证覆盖真实临时仓库的 gc、部分暂存、删除、新增、路径碰撞、越界路径、会话后编辑保护和撤回再撤回。跨进程外部写入仍有文件系统检查与写入之间的竞争窗口；遇到文件变化尽量拒绝，不声称跨进程事务。
