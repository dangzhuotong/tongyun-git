# 用户流程

需求编号见 [PRD](prd.md)。每个流程写入口、动作、状态变化和结果，并列出影响这条路径的失败和恢复。

## F1 核心流程：挑着提交并推送

入口：启动应用，最近仓库列表。

| 步骤 | 用户动作 | 应用状态变化 | 结果 | 需求 |
| --- | --- | --- | --- | --- |
| 1 | 打开最近仓库 | 检测 git、读取仓库状态 | 主界面显示改动列表、当前分支、领先落后数 | R-01、R-02 |
| 2 | 选中一个文件 | 计算该文件 diff | 右侧显示 diff | R-03 |
| 3 | 在 diff 里选第 2 个 hunk 的两行，按空格 | 写 index | 这两行出现在该文件的已暂存 diff 中，未暂存 diff 少了这两行 | R-05 |
| 4 | 另一个文件整体暂存（列表里按空格） | 写 index | 文件移到已暂存 | R-04 |
| 5 | 按 Ctrl/Cmd+K，再按 AI 生成 | 读取已暂存 diff，调用 AI | 信息框逐步填入提交信息 | R-07 |
| 6 | 修改标题，按 Ctrl/Cmd+Enter | 调用 `git commit`，hook 执行 | 新提交出现在日志顶部，已暂存清空，领先数 +1 | R-06 |
| 7 | 按 Ctrl/Cmd+Shift+K，确认 | 调用 `git push` | 领先数归零，操作日志多一条 | R-12、R-15 |

失败与恢复：

- 步骤 1，git 不可用 → 显示安装指引和手动指定路径（R-01）。
- 步骤 3，文件在选择后被外部改了 → 取消暂存操作并提示重新选择（R-05）。
- 步骤 5，AI 失败或超时 → 提示原因和设置入口，信息框原内容不变，用户可手写（R-07）。
- 步骤 6，hook 失败 → 显示 hook 输出，信息和暂存保留；用户修好后再提交（R-06）。
- 步骤 7，被拒绝 → 提示先拉取，进入 F3（R-12）。认证失败 → 显示 git 输出，用户在命令行或凭据管理器里修好认证后重试（R-11、R-12）。

## F2 切换或新建分支

入口：点标题栏分支名，或 Ctrl/Cmd+Shift+`。

1. 弹窗显示本地、远程分支，输入文字过滤。
2. 选本地分支回车 → 切换 → 标题栏和改动列表刷新（R-08）。
3. 选远程分支 → 自动创建跟踪分支并切换（R-08）。
4. 点「新建分支」→ 输入名称（实时校验）→ 创建并切换（R-09）。

失败与恢复：工作区改动会被覆盖 → 列出文件，保持当前分支，用户先提交（或等 v2 的 stash）；合并进行中 → 切换不可用并说明原因。

## F3 拉取并处理冲突（MVP 最小版）

入口：工具栏「拉取」或 Ctrl/Cmd+T。

1. 仓库没配置 pull 策略 → 首次弹窗选「合并 / 变基」，按仓库记住（R-11）。
2. 执行 `git pull`，显示进度，可取消。
3. 无冲突 → 日志和领先落后数更新。
4. 有冲突 → 顶部横幅「合并进行中，3 个冲突」，改动列表出现「冲突」分组：
   - 选冲突文件 → diff 显示冲突标记的内容 → 「用外部编辑器打开」。
   - 改好后在列表里暂存该文件（确认一次）→ 从冲突分组移出。
   - 全部解决 → 提交区自动带上合并默认信息 → 提交完成合并。
   - 或者点「中止合并 / 中止变基」→ 确认 → 回到拉取前的状态。

失败与恢复：网络或认证失败 → 显示 git 输出，状态不变；取消拉取 → 终止进程并提示可能需要重新拉取。

## F4 看历史

入口：Alt+9（macOS Cmd+9）切到日志。

1. 默认显示全部分支的树图；可切到只看当前分支。
2. 输入过滤词筛选标题、作者、哈希。
3. 选中提交 → 详情区显示信息和文件列表 → 点文件看只读 diff（R-10）。
4. 右键「从这里新建分支」进入 F2 第 4 步，起点为该提交（R-09）。

## F5 首次配置 AI

入口：第一次点「AI 生成」（还没配置时按钮显示「配置 AI」），或设置页。应用不内置 key，也不读环境变量（PRD D1）。

1. 设置页 AI 标签：选提供方（KIE / OpenAI 兼容接口 / Ollama）。
2. 按提供方填写：
   - KIE：模型名、key。
   - OpenAI 兼容接口：base URL（按服务商文档，例如 `https://api.deepseek.com/v1`）、模型名、key。
   - Ollama：地址（默认 `http://localhost:11434`），从下拉选本机模型；key 一般不填。
3. 地址下方显示最终请求地址；点「测试连接」→ 显示成功或具体原因（R-13）。key 保存进系统钥匙串，保存后输入框只显示「已保存」和「修改 / 清除」。
4. 第一次真正发送前弹窗说明会发送的内容和目标地址（Ollama 本机时注明「不出本机」），确认后发送；可勾选「不再提示」（R-07）。

失败与恢复：钥匙串不可用（Linux 无 Secret Service）→ key 输入框不可用并说明安装办法，或改用 Ollama；测试连接 401 → 提示检查 key；超时 → 提示可调高超时（本机 Ollama 首次加载模型较慢）。

## F6 修改上一次提交

入口：提交区「修改上一次提交」勾选框（Alt+M，macOS Ctrl+Option+M）。

| 步骤 | 用户动作 | 应用状态变化 | 结果 | 需求 |
| --- | --- | --- | --- | --- |
| 1 | 发现上次提交漏了文件，把它暂存 | 写 index | 文件出现在已暂存 | R-04 |
| 2 | 勾选「修改上一次提交」 | 读取 HEAD 信息，原草稿进撤销历史 | 信息框出现上次提交信息，按钮变为「修改提交」 | R-06 |
| 3 | 改信息（可不改），按 Ctrl/Cmd+Enter | 检查 HEAD 是否已推送；未推送直接执行 `git commit --amend` | 日志顶部的提交被替换，提交总数不变 | R-06 |

失败与恢复：

- HEAD 已推送 → 弹警告说明推送会被拒、本应用不提供强制推送；默认「取消」。用户取消后可改为新建一个提交。
- hook 失败 → 显示 hook 输出，HEAD 不变，信息和暂存保留。
- 仓库没有提交或合并进行中 → 勾选框不可用并说明原因。

## F7 丢弃改动并撤销

入口：改动列表里选中文件，右键「丢弃改动…」或 Ctrl+Alt+Z（macOS Cmd+Option+Z）。

| 步骤 | 用户动作 | 应用状态变化 | 结果 | 需求 |
| --- | --- | --- | --- | --- |
| 1 | 选中 2 个文件，触发丢弃 | 计算每个文件丢弃后的结果 | 确认框列出「恢复到上次提交」和「将删除」两组，标出无法快照的大文件；默认焦点在「取消」 | R-17 |
| 2 | 点「丢弃 2 个文件的改动」 | 先把这些文件的工作区和暂存区内容存成快照（`refs/tongyun/discard/*`），再恢复文件 | 文件从改动列表消失；提示条「已丢弃 2 个文件的改动 [撤销]」 | R-17、R-15 |
| 3（可选） | 10 秒内点「撤销」，或之后在命令面板选「撤销上一次丢弃」 | 把快照写回工作区和暂存区 | 两个文件回到丢弃前的状态，含已暂存的部分 | R-17 |

失败与恢复：

- 在确认框按 Esc、回车或点取消 → 什么都不发生。
- 撤销时某文件已被改过 → 列出这些文件，让用户选跳过或覆盖。
- 冲突文件或合并进行中 → 丢弃不可用，引导用「中止合并」（F3）。
- 快照写入失败 → 不执行丢弃，显示原因。

## F8 会话快照与撤回（V2-07，2026-10-11）

仓库工具 → 会话与搁置 → 输入名称 → 开始会话 → agent 修改临时工作区 → 结束会话 → 选择记录查看恢复预览 → 选择文件 → 确认恢复。结束后新增手动改动会禁止覆盖；HEAD 变化时拒绝恢复。需要反悔时选择「撤回备份」再恢复。快照不自动识别修改来源，会话期间手动编辑也纳入。

设置里打开自动检测时：claude、codex 或 tongyun-cli 启动，或短时间出现一批新改动，会自动开始会话；基线是这批改动之前的工作区。Cursor 开着不会因此开会话。Agent 退出、文件静默超时，或关掉自动检测，都会结束自动会话。已经有未结束的手动会话时不会再自动开一个。

## F9 搁置未暂存改动（V2-03）

会话与搁置 → 展开搁置 → 选文件 → 确认 → 文件恢复到 index 版本，暂存区不变 → 选择搁置记录 → 部分或全部取回。目标已有新改动时不覆盖。

## F10 提交与分支（R-18）

日志右键选提交 → 仓库工具 → 比较或应用/撤销/合并 → 明确确认 → 刷新状态。出现冲突时关闭工具进入三方解决器，解决暂存后继续；需要取消时确认中止。脏工作区禁止开始，提示先提交或贮藏。

## F11 工作区总览与逐行追溯（V2-08、V2-04）

仓库工具 → 总览 → 查看各分支/文件/领先落后/重叠提示 → 打开指定 worktree；或切到逐行追溯 → 输入文件路径 → 分页 blame → 点击提交编号查看详情。
